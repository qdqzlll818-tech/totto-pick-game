# 托托捞捞：第 4～9 关主题扩展设计

## 目标

在现有火锅局、大蒜局和水果局之后，增加六个按顺序解锁的主题关卡，形成“托托的四季小旅行”第一章。新关卡继续以“三个相同物品自动消除”为核心，不通过无限增加物品数量制造难度，而是逐步加入场景反馈、主题任务和轻量规则。

第 4～9 关依次为：

1. 雨天失物局
2. 梳妆台局
3. 画室局
4. 野餐局
5. 奶茶店局
6. 冬日毛线局

每关首次通关解锁一套对应托托皮肤。皮肤统一使用已确认的托托母版比例：圆润方头、短身、短脚、额头三颗点、`3` 字嘴，以及“左尖右圆”的非对称软结。

## 核心原则

- 第 4～9 关全部复用现有共用游戏引擎，通过关卡配置切换内容。
- 所有物品数量均为 3 的倍数，保证理论上可以完全清空。
- 主题托托每关固定出现 3 个，与普通物品共同参与堆叠、点击、晃动和三消。
- 所有露出可见区域的物品都可以点击，不以 DOM 层级简单阻断下层物品。
- 物品保持较大、立体、密集堆叠，不采用空心圆排列。
- 手机晃动必须识别为明显的翻锅动作；普通走路、拿手机和轻微抖动不触发翻动。
- 新机制只增加一层可理解的变化，不改变撤回、洗牌、移出和暂存的基本操作。
- 新关卡继续支持暂停、继续、重开、自动保存、账号同步和最佳成绩记录。

## 第 4 关：雨天失物局

### 叙事与场景

托托在雨天帮大家收失物，结果自己被埋进了装满雨具的透明伞筐。场景使用雾白、黄油黄、灰蓝和鼠尾草绿，容器表现为有水珠与浅水波的透明伞筐。

### 物品池

11 类普通物品各 12 个，加 3 个雨天托托，总计 135 个：

- 透明伞
- 折叠伞
- 雨靴
- 雨衣
- 小钥匙
- 帆布包
- 小黄鸭
- 青蛙
- 雨后树叶
- 水滴瓶
- 小云朵
- 雨天托托（特殊角色）

### 轻量机制

- 明显翻锅时，容器出现水波，物品产生有限滑动和相邻层变化。
- 水波只是视觉反馈，不自动消除，也不消耗洗牌次数。

### 奖励

- 首次通关：100 金币、雨天救援托托皮肤。
- 重复通关：25 金币。

### 轻量机制

## 关卡地图与解锁

- 首页地图按照 `hotpot → garlic → fruit → rain → vanity → studio → picnic → boba → winter` 顺序展示。
- 只有紧邻的上一关首次通关后，下一关才解锁。
- 已解锁关卡显示最佳得分和最佳时间；未解锁关卡显示明确条件。
- 衣柜始终展示全部皮肤轮廓，未拥有皮肤显示灰度预览、锁标记和来源关卡。
- 完成当前最后一关后显示“下一章正在准备”，不进入空白或无效链接。

## 共用功能与数据

- 每关使用独立存档键，存档中包含 `levelId`，防止串档。
- `level_progress` 继续按 `level_id` 同步完成状态、最高分和最佳时间。
- `user_skins` 继续保存皮肤 ID，不需要新增表。
- 游客登录后，本地和云端通关集合取并集；最高分取较大值，最佳时间取较小非空值。
- 奶茶订单的每日额外金币需要记录日期，防止刷新重复领取。
- “完美救援”徽章可先保存在进度扩展字段或独立本地数据中；未完成云端字段扩展时不阻塞通关。

## 晃动与输入

- 权限仍由玩家在关卡开始弹窗主动开启，登录时不自动请求。
- 普通走路与轻微抖动只允许产生极轻的视觉惯性，不触发碰撞声、不改变层级。
- 只有满足明显加速度、方向反转和短时连续性的翻锅手势，才执行有限物理翻动。
- 每次翻动最多提升 3～4 个物品，且只能变化一个相邻层。
- 晃动不影响收集槽、暂存区和订单数据。
- 拒绝权限、桌面端或不支持传感器时，玩家仍能完整通关。

## 美术与素材要求

- 每个普通物品使用独立透明背景 PNG/WebP，轮廓清楚并带圆润 3D 体积。
- 同一关内统一光源、视角、软阴影和材质，不混用写实照片、emoji 与平面图标。
- 物品在桌面与手机上都保持可辨识尺寸，不能为了容纳数量而缩小到图标级。
- 背景和容器负责体现主题，物品本身保持足够对比度。
- 图片加载失败时显示统一的主题占位图，不出现浏览器裂图标。

## 测试与验收

- 配置测试：九关顺序正确，每关总数与物品数量一致，所有数量均为 3 的倍数。
- 解锁测试：只有上一关完成时下一关可访问，直接修改 URL 不能绕过锁定。
- 存档测试：六个新关卡分别保存和恢复，不影响前三关存档。
- 点击测试：露出的下层物品可以点击，被完全遮挡的物品不会误选。
- 晃动测试：模拟走路不会触发翻动；明显翻锅动作才改变有限物品。
- 机制测试：灵感连击计分正确；奶茶订单不阻塞通关；冬日缠绕局面必定可解。
- 奖励测试：首次通关奖励皮肤与 100 金币，重复通关只奖励 25 金币。
- 资源测试：所有角色和物品资源在 GitHub Pages 上返回正确 MIME 类型且无 404。
- 设备测试：在 iPhone Safari、Android Chrome 和桌面浏览器完成至少一局。
